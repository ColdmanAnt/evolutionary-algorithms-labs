# Повторная сборка отчётов и проверка комплекта

Требуется Python 3.12+. Из корня репозитория после активации окружения:

```sh
python -m pip install -r requirements-dev.txt
python tools/build_reports.py
```

`requirements-dev.txt` включает закреплённые основные зависимости, ReportLab и pypdf. Скрипт читает `report_content.json` каждой работы и включённые PNG. Шрифт DejaVu Serif берётся из Matplotlib и встраивается в PDF. После установки зависимостей внешняя сеть при сборке не нужна. Итог — четыре файла в `reports/` и общий `all_reports.pdf`.

Проверка серий запусков, точных бюджетов, содержания PDF и всех 88 тестов:

```sh
python tools/verify_bundle.py
```

Результат сохраняется в `verification.json`: версии среды, протокол всех тестов, независимые проверки каждой работы, целостность отчётов и SHA256 проверенных файлов.

Переносимый повтор всех 560 экспериментов с исходными seed:

```sh
python tools/verify_bundle.py --replay
```

Сохранённые данные, метаданные и внутренние связи файлов проверяются строго во всех режимах. В `--replay` каждый эксперимент ЛР1/ЛР4 выполняется дважды: в текущей среде должны точно совпасть конечные векторы, fitness и полные истории. Проверяются фактические бюджеты, границы и независимые скалярные оракулы. Различия с архивом выводятся отдельно по каждому seed и не выдаются за совпадение.

Для среднего каждой конфигурации ЛР1/ЛР4 задан инженерный regression guard: `abs(mean_повтора − mean_архива) <= max(ε, 3 × s_архива / √n)`, где `s` — выборочное стандартное отклонение архива; ЛР1: `n=20, ε=1e-9`, ЛР4: `n=30, ε=1e-11`. Порог фиксирован до повторов. Это контроль дрейфа среднего, а не проверка статистической эквивалентности. Случайный поиск ЛР1 дополнительно сохраняет строгую проверку архивных fitness и checkpoint в малом допуске.

Чтобы также потребовать совпадения всех архивных траекторий ЛР1/ЛР4 в объявленных малых допусках:

```sh
python tools/verify_bundle.py --strict-archive
```

Этот флаг включает полный повтор. Допуски: ЛР1 `abs=2e-12, rel=1e-12`; ЛР4 `abs=1e-11, rel=1e-10`. Они не означают, что побитовые траектории обязаны переноситься между машинами. Исторические сведения и незаписанные детали исходной среды приведены в [reference_environment.json](../reference_environment.json); ограничения гарантий RNG описаны в [документации NumPy](https://numpy.org/doc/stable/reference/random/compatibility.html).

Повторный поиск не перезаписывает исходные CSV, NPZ, графики и времена; обновляются протоколы `labN/audit.json` и `verification.json`. В CI используется `--replay`. Для отдельной работы доступны `python labN/audit_saved.py` и `python labN/audit_saved.py --replay`; ЛР1/ЛР4 также принимают `--strict-archive`. PDF автоматически не пересобираются: несоответствие исходному JSON или рисункам является ошибкой проверки. После намеренного изменения материалов сначала пересоберите отчёты.

После успешного GitHub Actions протоколы этой машины доступны как артефакт `verification-<commit SHA>` внизу страницы запуска; срок хранения — 14 дней. В нём есть объявленные численные допуски и фактически измеренные различия повторов. Основные SHA256 протокола рассчитаны для LF-нормализованного текста Git и точных байтов бинарных файлов.
